# 私有快照云端并发与上传结果未知治理

## 结论

图语家的两个账号私有快照已补齐同账号并发替换和“服务器已提交、客户端响应丢失”两类关键边界。并发上传后只保留一个完整、可由对端解密的最新快照；上传调用抛出网络异常时，客户端不再错误保证云端未改变，而是如实提示结果未知并引导先下载核对。恢复密码遗失警告经当前源码复核已在 Web 和微信实现，不再列为代码缺口。

## 变动 1：复核恢复密码遗失保护并纠正文档旧状态

- **意图：** 确认覆盖矩阵中的“忘记密码提示待验收”究竟是代码缺失还是历史记录未回填，避免重复造 UI。
- **决策：** 直接审阅 CBoard Web Export 消息/表单、中文翻译、共享密码校验、微信 backup 页面和现有双次输入；确认双端都已有“密码不会上传或保存、遗忘后无法恢复”说明和上传时二次输入，不新增另一套恢复口令 UI。
- **理由：** 端侧加密没有服务端找回能力；正确做法是上传前显著告知并核对，而不是提供会削弱端到端加密的后门。当前实现已经复用 CBoard 表单、Taro Input 和共享 `validatePrivateArchivePassphrase`。
- **证据：** Web `Export.messages.js` 明确 `cannot be recovered`，`zh-CN.json` 说明密码不上传/不保存，Export 表单要求恢复密码及确认；微信 `library/index.tsx` 两个独立快照均显示“遗忘后无法找回”，并分别提供密码和再次输入。共享密码测试覆盖至少 12 字符及两次输入不一致。
- **生效范围：** 覆盖矩阵隐私分层状态和恢复密码用户告知；不改变加密算法、密码长度、表单布局、API 或现有翻译。

## 变动 2：修正上传网络异常的错误确定性文案

- **意图：** 防止响应在服务端提交后丢失时，客户端错误告诉照护者“已有云端备份没有改变”，进而造成误判或无谓覆盖。
- **决策：** 复用现有 cloud port 的异常边界和“下载、复核并恢复”入口，把异常文案改为：本机数据没有改变，但云端结果未知、可能已经更新，应先核对再决定是否重试。
- **理由：** 网络异常只能证明客户端没有收到可靠响应，不能证明服务器没有执行。把不确定结果表述为成功或失败都会误导；现有下载路径会先读取元数据、校验 SHA-256、下载密文并在本机解密，正好可作为核对入口，无需新增协议或 API。
- **证据：** 新增 cloud port 单测模拟 `uploadArchive` 抛出响应丢失错误，断言不再出现“云端未改变”，而返回有界、可操作的结果未知提示。聚焦测试为 `10 passed / 4 external skipped`，TypeScript 和目标 ESLint 通过。
- **生效范围：** 微信私人图片和完整私有数据两个 cloud port 共用的上传异常提示；不改变成功响应、HTTP 状态映射、本机数据、Web UI 或服务端行为。

## 变动 3：真实验证同账号并发替换保持单一完整快照

- **意图：** 补齐两个设备或重复操作同时上传时，Mongo 元数据与 Blob 可能分叉、拼接或指向损坏密文的证据缺口。
- **决策：** 继续复用 cboard-api 的 `findOneAndUpdate` 单文档原子替换、唯一用户索引、旧 Blob 清理和现有 SHA-256 完整性校验；在显式云端集成门中并发上传两份不同的 `PIE2EE01` 私人图片密文，然后读取最终元数据、下载胜者并由微信端解密。
- **理由：** 私有快照是“每账号一个最新版本”而非 CRDT；并发时允许最后一个原子写入成为胜者，但绝不能产生半份密文、元数据/Blob 不一致或不可恢复结果。验证现有成熟 Mongo/Azure 语义比新增锁服务或自研队列更小。
- **证据：** 真实 Node API、Mongo 4.4、Azurite 3.35.0 和 HTTP 下，两次并发 `POST /communication/private-library` 均为 200；最终 metadata SHA-256 对应其中一份完整密文，下载为 231 字节完整 Blob，并由微信 adapter 解密为对应原始 ZIP。Azurite 记录两个 201 上传、旧 Blob 202 删除和胜者 200 下载。
- **生效范围：** 同一账号私人图片快照的并发替换证据，以及相同 controller 被完整私有数据端点复用的可信度；不新增版本历史、合并语义、分布式锁或客户端自动冲突选择。

## 变动 4：真实验证服务端提交后响应丢失与安全重试

- **意图：** 证明弱网中最危险的“服务器已经写入，但客户端认为失败”不会损坏或丢失账号私有快照。
- **决策：** 在真实 HTTP 上传完成并返回 200 后，由测试依赖故意丢弃响应并抛出网络异常；客户端先得到结果未知提示，再通过现有 metadata 读取确认 SHA-256，随后以同一密文重试并下载、跨端解密。
- **理由：** 直接在服务器前中断请求只能证明未提交，不能覆盖不确定提交窗口；在真实提交后丢响应准确模拟该分布式边界。相同密文重试继续复用服务端原子替换和旧 Blob 清理，不引入测试专用接口。
- **证据：** 首次真实 `POST /communication/private-device-data` 为 200，但测试端丢弃响应；随后 metadata 为 200 且大小/SHA-256 与本机密文一致；同密文重试再次为 200，下载 236 字节并由 Web adapter 解密为原 ZIP。扩展云端集成为 `1 file / 4 tests passed`。
- **生效范围：** 微信两个账号私有快照的上传异常语义、核对路径和重复请求安全性；不声称真实蜂窝网络、超时代理、断点续传或生产 Azure 已验收。

## 变动 5：全量质量门与隔离环境清理

- **意图：** 确认提示修复和测试扩展不破坏生产包，并避免一次性云端环境残留。
- **决策：** 执行微信完整测试、质量门、TypeScript、ESLint、平台边界和 Taro production build；提取日志后只停止已由 PID、健康检查和唯一容器名核验的 API、Azurite、Mongo。
- **理由：** cloud port 位于生产微信依赖图，必须同时验证包体和平台边界；隔离运行时应退出即删除，防止后续测试误用旧 Blob 或数据库。
