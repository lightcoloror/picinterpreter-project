# 图语家 PRD：基于 Cboard 的二次开发版

状态：草案  
日期：2026-05-09  
依据：ADR-003 `Use Cboard as the AAC Base for Secondary Development`  
范围：后续生产化方向，不等同于当前自研原型的功能清单

## 1. 一句话定位

图语家是在 Cboard 成熟 AAC 沟通板底盘之上，面向中文成人失语、医疗照护和家庭照护场景扩展的双向辅助沟通系统。

Cboard 负责成熟的 AAC 板系统：

- 沟通板
- 卡片
- 文件夹式导航
- 板编辑
- 图片和语音基础能力
- 一个卡片出现在多个板
- 板作为卡片跳转

图语家负责 Cboard 不覆盖的中文照护层：

- 中文核心词库和成人照护场景板
- 中文词语到图片的匹配与消歧
- 患者选图到自然中文句子
- 照护者文字或语音到图片序列
- 个人偏好图片映射
- 医疗、求助、修正澄清等高风险场景优化
- 高风险词回归测试和词库策展护栏

## 2. 背景与决策

项目早期采用自研架构，是为了快速验证图语家的核心产品能力：

- 患者通过图片表达
- 系统把图片序列生成自然句子
- 照护者输入句子后转换为图片序列展示给患者
- 中文词图匹配需要处理歧义，例如 `开心` 不能匹配到 `开心果`

随着原型推进，项目不断遇到 AAC 板系统本身的问题：

- 板是否是一等公民
- 板上内容是否应该显式策展
- 一个卡片是否可以出现在多个板
- 板是否可以作为卡片跳转
- 板内卡片是否支持任意混排
- 语义分类和展示位置是否应该分离

这些问题并不是图语家的差异化创新，而是成熟 AAC 板系统的基础能力。Cboard 已经较好地解决了这些底盘问题。

因此，后续生产化方向改为：

**复用 Cboard 作为 AAC board-system 底盘，在其上开发图语家的中文语义、照护者协作和临床词库层。**

## 3. 目标用户

### 3.1 主要用户：患者

典型用户：

- 成人失语患者
- 中风后语言表达困难者
- 医疗、康复、护理场景中的暂时或长期表达困难者
- 能看图、指图、点按屏幕，但难以稳定说话或打字的人

患者侧需求：

- 快速表达需求和不适
- 低认知负担
- 大按钮、稳定位置
- 能在紧急、疼痛、如厕、吃喝、休息等场景下直接表达
- 不被复杂设置、技术错误和编辑界面打扰

### 3.2 主要协作者：照护者

典型用户：

- 家属
- 护工
- 护士
- 康复师
- 语言治疗师

照护者侧需求：

- 快速理解患者表达
- 用图片向患者解释一句话
- 维护患者个人偏好图片
- 添加常用表达
- 纠正错误匹配
- 在低技术门槛下调整沟通板

### 3.3 次要用户：项目维护者 / 词库策展者

需求：

- 按成熟 AAC 结构维护默认词库
- 有规则地处理近义词、同义词和歧义词
- 有测试防止词图错配回退
- 能把当前原型中的词库资产迁移到 Cboard 结构中

## 4. 产品原则

### 4.1 Cboard 底盘优先

不重新实现 Cboard 已经成熟解决的 AAC 板系统能力。

优先复用：

- board / tile 数据模型
- board navigation
- tile loadBoard
- board editor
- image and symbol management
- card reuse
- board import / export 能力

### 4.2 Board-first，不做纯分类浏览器

患者看到的是沟通板，不是数据库分类。

默认入口应是首页板，首页板包含：

- 高频直接表达卡
- 核心词入口
- 修正澄清入口
- 身体医疗入口
- 吃喝入口
- 日常护理入口
- 家人与人物入口
- 常用表达入口

### 4.3 卡片、图片、板块三者分离

必须支持：

- 同一张卡片出现在多个板
- 不同词条使用同一张图片
- 板块本身作为卡片跳转
- 卡片展示位置不等于语义分类
- 不为了避免重复图片而选择更不准确的图片

### 4.4 中文语义层由图语家负责

Cboard 的板系统不负责中文语义消歧。

图语家必须保留并发展：

- 中文别名
- 真同义词
- 相关词但非同义词
- 排除义项
- 语义领域
- 高风险词测试

### 4.5 患者端稳定，照护者端可编辑

患者端默认应简洁稳定。  
编辑、调试、AI 配置、同步配置应主要放在照护者界面。

## 5. 范围划分

## 5.1 由 Cboard 承担的基础能力

### 板系统

需求：

- 支持多个 board
- 支持 root board / home board
- 支持 board 内有显式 tiles 列表
- tile 可以是发音卡片
- tile 可以是跳转到另一个 board 的入口
- 支持导航历史和返回
- 支持隐藏板，但隐藏板可通过入口进入

验收标准：

- 可以创建一个首页板，混排语音卡片和跳转卡片
- 一个卡片可以在两个以上 board 中出现
- 一个 board 可以作为 tile 出现在另一个 board 中
- 板内顺序由 board 的 tiles 决定，而不是由点击热度或数据库分类自动决定

### 卡片与图片

需求：

- 卡片包含 label / vocalization / image
- 支持本地图片或外部图片
- 支持同一图片被多个卡片使用
- 支持同一卡片在不同 board 中出现
- 支持卡片编辑

验收标准：

- `开心` 和其他合适概念可以复用同一图片，只要语义准确
- `换` 和 `换衣服` 可以共用同一图片，不因为图片重复而换成不准确图片
- 同一卡片可同时出现在首页、快速表达、场景板

### 板编辑与管理

需求：

- 照护者可以编辑板内容
- 可以调整卡片顺序
- 可以新增、删除、移动卡片
- 可以新增跳转到其他板的入口
- 可以隐藏不常用板

验收标准：

- 不需要修改词条语义字段，也可以调整某个板上展示哪些卡
- 调整顺序后，患者端默认按手动顺序显示
- 热度排序只能作为可选开关，不是默认排序

## 5.2 由图语家承担的扩展能力

### 中文默认词库

需求：

- 提供面向中文成人照护的默认 AAC 词库
- 覆盖快速表达、核心词、修正澄清、身体医疗、吃喝、日常护理、人物、地点、情绪、时间、描述词等
- 词库结构参考成熟商业 AAC 产品，而不是简单按物品分类

首批核心板：

- 首页
- 快速表达
- 核心词
- 修正澄清
- 身体医疗
- 吃喝
- 日常护理
- 家人与人物
- 情绪
- 地点
- 活动
- 时间
- 描述词

验收标准：

- 首页能覆盖患者最高频需求
- 修正澄清板包含 `不对`、`不是这个`、`再说一次`、`写下来`、`指给我看`、`给我选项` 等策略
- 身体医疗板包含疼痛、不舒服、头晕、恶心、呼吸、跌倒、危险等高风险表达
- 快速表达只放一键短语，不混成普通词库垃圾桶

### 中文词图匹配与消歧

需求：

- 支持精确匹配
- 支持真同义词匹配
- 支持词库主词归一
- 支持语义领域加权
- 支持排除义项
- 支持高风险词回归测试

必须避免：

- `开心` 匹配到 `开心果`
- `脚踝` 匹配到 `鞋`
- `充电` 匹配到 `充电器`
- `房子` 匹配到 `房间`
- `洗头` 匹配到 `洗发水`

验收标准：

- 高风险词测试全部通过
- `synonyms` 只保存真正可互换的同义词
- 相关但不可互换的词只能放入 `relatedTerms` 或备注，不参与自动匹配
- 某个词如果是另一个词条的主标签，不能随意作为别的词条 synonym

### 患者选图到自然句子

需求：

- 患者选择一组图片后，系统生成自然中文候选句
- 支持本地模板兜底
- 支持在线 AI 增强
- 支持播放候选句
- 支持收藏常用表达

验收标准：

- 选择 `我`、`想`、`喝水` 可生成 `我想喝水`
- 选择 `我`、`痛`、`肚子` 可生成自然的求助句
- AI 不可用时仍能生成可理解句子
- 患者端不暴露技术错误

### 照护者句子到图片序列

需求：

- 照护者输入中文句子，系统转换成图片序列
- 支持语音输入转文字
- 支持图片序列全屏展示给患者
- 支持照护者纠错和换图
- 支持记录纠错结果

验收标准：

- 输入 `你哪里不舒服` 能生成面向患者可理解的图片序列
- 输入 `你想喝水还是上厕所` 能尽量拆成可指认的图片序列
- 未匹配词有清晰的照护者处理入口
- 全屏展示时患者不看到编辑控件

### 个人偏好图片映射

需求：

- 患者可以对某个概念使用个人更熟悉的图片
- 私有图片默认不进入公共词库
- 个人偏好图片优先于默认图片
- 支持照护者维护

验收标准：

- `妈妈` 可以映射到患者真实家属照片
- `家` 可以映射到患者自己的家
- 私有图片不会错误同步为公共资源
- 删除偏好图后回退到默认图

### 隐私与同步

需求：

- 默认本地优先
- 支持匿名设备使用
- 私有图片和私有词条不进入公共同步
- 同步表达记录和常用表达时保留隐私边界

验收标准：

- 未登录也可以使用核心表达功能
- 私有图片不会上传到公共图库
- 家庭内部共享和公共词库贡献是两个不同动作

## 6. 核心用户流程

### 6.1 患者表达流程

1. 患者打开首页板
2. 点击高频卡片或进入场景板
3. 选择一个或多个图片
4. 系统生成候选中文句子
5. 系统播报句子
6. 照护者理解并响应
7. 表达可保存为常用语

成功标准：

- 常见表达三步以内完成
- 紧急表达一键或两步以内完成
- 患者不需要理解分类系统

### 6.2 照护者向患者解释流程

1. 照护者输入或语音说一句话
2. 系统拆成图片序列
3. 照护者检查并纠正
4. 全屏展示给患者
5. 患者通过指图、点图或表情反馈理解
6. 系统记录确认后的接收记录

成功标准：

- 句子到图片不是一次性黑箱结果，照护者可以修正
- 患者看到的是清晰图片序列，不是调试界面

### 6.3 照护者维护词库流程

1. 照护者进入编辑模式
2. 添加或修改卡片
3. 选择图片
4. 填写标签、发音、同义词和语义领域
5. 决定卡片出现在哪些板
6. 调整板内顺序

成功标准：

- 板上出现位置不要求修改语义分类
- 可复用已有图片
- 可让一个卡片出现在多个板

## 7. 数据需求

### 7.1 Cboard 基础数据

需要理解并复用 Cboard 的核心对象：

- communicator / user profile
- board
- tile
- image
- loadBoard
- navigation history

### 7.2 图语家扩展数据

图语家需要在 Cboard 基础上增加或旁路维护：

- Chinese lexical metadata
- semanticDomain
- synonyms
- relatedTerms
- excludedMeanings
- personalImagePreference
- receiverCorrection
- missingToken
- highRiskTokenTestCase
- privacy scope

具体字段命名可以随 Cboard 结构调整，但语义必须保留。

## 8. 默认板结构

### 8.1 首页板

首页板不是分类列表，而是最高频沟通入口。

应包含：

- 是
- 不是 / 不
- 要
- 不要
- 帮帮我
- 停止
- 再说一次
- 我痛
- 我不舒服
- 我要喝水
- 我想上厕所
- 请叫医生
- 请叫家人
- 快速表达入口
- 核心词入口
- 修正澄清入口
- 身体医疗入口
- 吃喝入口
- 日常护理入口
- 家人与人物入口

### 8.2 快速表达板

职责：一键表达完整短语。

不应混入大量普通单词。

### 8.3 核心词板

职责：高频语法骨架词和生成性表达。

例如：

- 我
- 你
- 他/她
- 要
- 想
- 可以
- 不
- 有
- 去
- 来
- 给
- 看
- 说
- 哪里
- 什么
- 为什么

### 8.4 修正澄清板

职责：当系统或照护者理解错时，患者能修正。

必须优先保证可达。

### 8.5 场景板

场景板按沟通场景组织，不按物品分类组织。

例如：

- 身体医疗
- 吃喝
- 日常护理
- 家人与人物
- 地点
- 活动
- 情绪

## 9. AI 需求

### 9.1 AI 是增强，不是单点依赖

所有关键沟通流程必须有本地兜底。

AI 可用于：

- 图片序列生成自然句子
- 照护者句子重分词
- 未匹配词候选建议
- 候选句改写

AI 不应负责：

- 决定患者端唯一表达
- 覆盖人工策展词库
- 绕过高风险词测试
- 未经确认写入患者长期偏好

### 9.2 服务端配置

AI Key 不放在患者端。

需求：

- 服务端配置 API Key
- 前端只调用后端接口
- 未配置 AI 时自动使用本地模板

## 10. 许可与合规

### 10.1 Cboard

项目可以基于 GPL 兼容方式复用 Cboard 代码。

要求：

- 保留 Cboard 许可声明
- 遵守 GPL 分发义务
- 标明图语家二次开发部分

### 10.2 图符资源

需要记录每张图片来源和许可。

至少支持：

- ARASAAC
- OpenSymbols
- 用户上传图片

要求：

- 图片来源可追溯
- 署名信息可展示
- 私有图片不进入公共图库

## 11. MVP 范围

### 必须做

- Cboard 能本地跑通
- 图语家中文默认首页和核心板能导入 Cboard
- 患者能选图并播报
- 一个卡片能出现在多个板
- 板可以作为 tile 跳转
- 默认排序是人工策展顺序
- 中文词图匹配核心测试能迁移
- `开心 -> 开心果` 等高风险错配有测试保护
- 患者选图能生成中文句子，至少有本地模板兜底
- 照护者能输入中文并得到图片序列的初版流程

### 可以延后

- 完整云同步
- 多家庭成员权限
- 完整治疗师工作台
- 大规模公共词库贡献系统
- 自动学习所有个人偏好
- 全量 OBF 兼容
- 打印版导出
- 复杂眼控或开关扫描优化

## 12. 非目标

本阶段不做：

- 复制 Cboard 默认英文词库作为图语家默认词库
- 以图片去重为目标牺牲语义准确性
- 要求一张卡片只能属于一个板
- 要求一个概念只能使用一张图片
- 把患者端做成复杂编辑器
- 完全依赖 AI 生成沟通结果
- 用普通图片分类替代场景板设计

## 13. 验收标准总表

| 模块 | 验收标准 |
|---|---|
| Cboard 底盘 | 能运行、能显示 board、能导航、能编辑基础卡片 |
| 首页板 | 混排卡片和板入口，顺序稳定 |
| 多板引用 | 同一卡片可出现在多个板 |
| 共享图片 | 不同卡片可引用同一图片 |
| 中文词库 | 默认板结构覆盖成人照护核心场景 |
| 词图匹配 | 高风险错配测试通过 |
| 患者表达 | 选图后可生成并播报中文句子 |
| 照护者接收 | 输入中文后可生成图片序列并全屏展示 |
| 个人图片 | 私有偏好图可覆盖默认图 |
| 隐私 | 私有图片和私有词条不进入公共同步 |

## 14. 迁移计划

### 第一步：建立 Cboard 基线

- fork 或引入 Cboard
- 本地运行
- 理解 board / tile / image 数据结构
- 确认 GPL 许可文本和保留方式

### 第二步：迁移默认板

- 首页
- 快速表达
- 核心词
- 修正澄清
- 身体医疗
- 吃喝
- 日常护理
- 人物

### 第三步：迁移中文语义层

- seed 词库元数据
- synonyms / relatedTerms / excludedMeanings
- semanticDomain
- 高风险词测试

### 第四步：接入图语家双向流程

- 患者选图到句子
- 照护者文本到图片
- 纠错记录
- 常用表达

### 第五步：补齐隐私与同步

- 私有图片
- 个人偏好图
- 本地优先数据
- 可选云同步

## 15. 成功指标

产品成功不是“功能多”，而是患者和照护者能稳定沟通。

优先指标：

- 患者能否在 1-3 步内表达常见需求
- 医疗和紧急表达是否可快速到达
- 照护者输入句子后图片序列是否可理解
- 高风险词是否不再错配
- 照护者是否能维护个人偏好图
- 默认词库是否贴近中文照护场景

## 16. 总结

图语家的下一版不应继续把工程重点放在自研 AAC 板底盘上。

Cboard 已经提供了成熟的 board-first 基础。图语家的价值应集中在：

- 中文
- 成人照护
- 失语沟通
- 语义消歧
- 双向图文重构
- 个人化图片
- 高风险词库护栏

因此，本 PRD 的核心方向是：

**用 Cboard 承担 AAC 板系统，用图语家扩展中文照护智能层。**
