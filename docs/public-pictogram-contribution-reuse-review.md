# 公共图符贡献开源复用审查

- 审查时间：`2026-07-22 08:41:19`
- 执行工具 / 模型：`Codex（GPT-5.6）`
- 证据状态：官方站点、官方 GitHub 仓库与图语家当前 PRD

## 意图

判断图语家能否直接复用成熟 AAC 项目的公共图符投稿与审核能力，而不是自行研发上传、审核、许可、删除和申诉系统。

## 决策

当前不在 CBoard Web、微信小程序或 cboard-api 新增公共投稿 endpoint。继续复用公共图源搜索与许可展示；家庭照片和个人图卡保持本机或用户主动的账号私有备份。未来只有满足以下任一条件才进入实现：

1. OpenSymbols 或其他可信 AAC 上游正式提供稳定投稿、审核和删除 API，可由图语家编写薄 adapter。
2. 项目明确批准独立 moderation 服务，并确定运营责任、许可协议、患者隐私、内容安全、删除申诉、审计与长期存储预算。

## 理由

公共投稿不是普通文件上传。患者正脸、家庭环境和私人物品可能包含敏感信息；图符又必须记录作者、许可、来源、语言与语义审核。没有成熟上游接口时自行增加 Blob 上传只会形成一个无法安全运营的半成品。

## 证据

- [OpenSymbols 开源仓库](https://github.com/open-aac/opensymbols)采用 MIT 许可，当前 README 描述 Rails 聚合/搜索服务、S3 `/libraries` 与 manifest 导入，适合继续作为公共图源和未来独立服务参考。
- [OpenSymbols 官方站点](https://www.opensymbols.org/)说明新图符提交仍是计划功能，现阶段提供“请求一个不同图符”的反馈表，不是可直接复用的投稿 API。
- [ARASAAC public-api](https://github.com/Arasaac/public-api)公开的是 ARASAAC 检索服务代码，当前未找到面向第三方用户投稿与人工审核的稳定契约。
- [Global Symbols 的 CBoard 集成指引](https://globalsymbols.com/knowledge-base/3OICPNYW5GxncqOPgu3qWK?locale=es)描述通过图库 API 或离线下载把符号集接入 CBoard，不等同于公共投稿系统。
- 图语家 `docs/prd-cboard-secondary-development.md` 要求私有图片不进入公共图库，并把大规模公共词库贡献系统列为 MVP 可延期项。

## 生效范围

适用于 CBoard Web、微信小程序、cboard-api 和未来服务的公共图符贡献边界。现有本机个人图片、缺词在线候选、来源许可展示、结构化图库导入和账号私有 custom ZIP 保持不变。本审查不代表永远取消公共贡献；它要求未来优先复用可信上游或独立成熟 moderation 服务，不把患者图片直接接入公共 Blob。

## 2026-07-26 09:46:41 | 复审记录

- 执行工具 / 模型：`Codex（GPT-5.6）`
- 证据状态：官方站点、官方 GitHub 仓库及当前 CBoard / cboard-api 实现复核

### 意图

在 CBoard 已经具备公开板浏览、复制、图片代理、发布和举报后，重新判断这些成熟代码能否直接构成图语家的“公共图符贡献”闭环，避免把已有能力漏判为缺失，也避免把整板公开误称为逐图投稿审核。

### 决策

- 维持 2026-07-22 的边界：当前不新增图语家公共图符上传或投稿 endpoint。
- CBoard 的公开板列表、公开 bundle、受限图片代理、整板发布/复制和举报继续直接复用，但只定位为“公开沟通板发现与复用”，不定位为“公共图符投稿与审核”。
- 只有可信 AAC 上游提供稳定的投稿、审核、删除和许可 API，或项目另行批准有明确运营主体的 moderation 服务后，才新增薄 contribution adapter。
- 本机个人图卡、账号私有 ZIP 和公共贡献继续保持三个独立动作，任何家庭照片都不得因公开板或缺词补图流程被自动公开。

### 理由

- CBoard 的 `isPublic` 是整板可见性开关，举报路径是邮件通知；现有代码没有逐图许可确认、待审状态、审核队列、删除申诉、敏感图片拦截和审计记录。
- 把整板公开能力直接改造成患者图片投稿，会绕过作者授权、许可、隐私、内容安全和运营责任，技术上能上传不等于形成可上线的公共贡献产品。
- 上游没有成熟接口时，自行建立 moderation 服务将成为长期运营系统，不符合“优先复用成熟开源、减少自研”的工程原则，也不是双向沟通核心的阻塞项。

### 证据

- [OpenSymbols 官方站点](https://www.opensymbols.org/)当前仍把图符提交描述为计划能力；[OpenSymbols 官方仓库](https://github.com/open-aac/opensymbols)提供图库聚合和搜索实现，没有可直接复用的第三方投稿审核契约。
- [ARASAAC public-api](https://github.com/Arasaac/public-api)公开的是检索 API，没有发现第三方用户投稿、人工审核、删除和申诉的稳定接口。
- 当前 CBoard `publishBoard` 只更新公开状态；cboard-api 的公开板接口提供列表、bundle 和图片读取，`reportPublicBoard` 只发送举报邮件。这些代码足以支撑公共板复用，但不足以证明公共图符贡献闭环。
- 图语家现有代码已经覆盖本机个人图卡、设备私图、账号私有 custom ZIP、公共板导入、公开许可图卡收纳和来源展示，因此暂缓公共投稿不会阻断患者表达、接收理解或照护图库维护。

### 生效范围

- 生效于 CBoard Web、微信小程序、cboard-api 及未来图符服务的公开发布、图库复用和贡献边界。
- 不删除或限制现有公开板浏览/复制/举报、受限图片代理、缺词联网候选、ARASAAC/OpenSymbols 检索、本机个人图片或账号私有备份。
- 公共图符贡献继续标记为“有条件延期”，不冒充已完成，也不以自行上传 Blob 作为临时替代。
- 本轮只做代码与官方资料复审和文档更新，未新增 endpoint、依赖、插件或媒体，未预览、上传、发布、部署、提交或推送；全程后台执行，没有打开、激活、聚焦、抬升或置顶任何窗口。
